# AGENTS.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal NixOS + Home Manager configuration for a single host (`nixos`, x86_64-linux, Hyprland desktop, NVIDIA). There is no test suite; verification means evaluating/building the Nix outputs. Applying changes (`nixos-rebuild switch`, `home-manager switch`) needs the owner's sudo/consent — build and verify, but don't apply unless asked.

## Multiple independent flakes

This repo is **not** one flake. Each flake has its own `flake.lock`, and the root flake does NOT pull in the others:

| Flake | Output | Applies to |
|---|---|---|
| `./flake.nix` | `nixosConfigurations.nixos` (modules in `system-config/`) | the whole system |
| `home-config/mathew/` | `homeConfigurations.mathew` | desktop user `mathew` (Hyprland, waybar, kitty, stylix…) |
| `home-config/openclaw/` | `homeConfigurations.openclaw` | OpenClaw AI-agent gateway user (consumes `nix-openclaw`, `kokoro` via `path:../../kokoro`) |
| `home-config/openclaw-npm/` | `homeConfigurations.openclaw-npm` | npm-based OpenClaw dev user (MAUI/Android SDK, Rider, nix-ld) |
| `kokoro/` | Russian TTS packages/CLI | used by the openclaw flake |

`home-config/shared/*.nix` (git, zsh, ssh, maui-dev) are plain modules imported by several user configs. `system-config/configuration.nix` is the import list for system modules; commented-out imports are intentionally disabled.

Common commands (run from the repo root):

```sh
nixos-rebuild build --flake .#nixos                  # build only; `switch` needs sudo
nix eval .#nixosConfigurations.nixos.config.<opt>    # inspect an option
home-manager build --flake ./home-config/mathew#mathew
home-manager build --flake ./home-config/openclaw#openclaw
home-manager build --flake ./home-config/openclaw-npm#openclaw-npm
nix flake update --flake ./home-config/openclaw-npm  # per-flake lock update ("Update flake" commits)
```

Evaluating `programs.openclaw` under the root flake fails ("attribute 'openclaw' missing") — that's the wrong flake; use `home-config/openclaw`.

## OpenClaw specifics

- `~/.openclaw/openclaw.json` is a symlink into `/nix/store` (`OPENCLAW_NIX_MODE=1`); `openclaw config set` and doctor repairs are refused. Edit the Nix source (`home-config/openclaw/openclaw.nix`) instead.
- `home-config/openclaw/scripts/config-check.sh` (and the copy in `openclaw-npm/scripts/`) validates a config on an isolated temp state dir without touching `~/.openclaw`; keep the two copies in sync.
- Ports are defined only in `home-config/openclaw/local/ports.nix`; model definitions in `local/ai/models.nix`.
- Per-agent instruction files (coordinator, coder, researcher, reviewer, advisor) live in `home-config/openclaw/openclaw-local/workspace/<role>/`. Edit these repo sources, never the read-only deployed copies.
- Agent skills in `home-config/openclaw/skills/` document repo workflows (e.g. `nixos-system-config`, `nix-openclaw-config`, `nix-dev-env-tooling`) — read the relevant one before non-trivial changes. Workshop skills at runtime live under `~/.openclaw`, not in the repo.
- Gateway npm package is built from `home-config/openclaw/npm/` (pinned `package-lock.json`, `patch-openclaw-npm-dist.mjs`, `patches/`).

## Conventions and gotchas

- Before hand-writing a systemd unit, check whether the pinned nixpkgs already has an upstream module/option for it.
- Layering: `environment.systemPackages` / `systemd.tmpfiles.rules` are system-level only (not valid in Home Manager). tmpfiles rules must create the full directory chain.
- Secrets use agenix: `secrets.nix` lists recipients (host key only), encrypted files in `secrets/*.age`. Never print or commit plaintext secrets. `sing-box` config is generated by `system-config/sing-box/generate-config.py` from agenix credentials.
- `git status` may show lock-file changes you didn't make (e.g. `flake.lock`); report them separately rather than folding them into your change.
- The repo has no git identity for the `openclaw` users; use a one-off `git -c user.name=… -c user.email=…` rather than writing git config.
- Large binary assets (`*.sofa` HRTF files, `Wallpapers/`) are tracked in the repo root; `result` symlinks are gitignored.
