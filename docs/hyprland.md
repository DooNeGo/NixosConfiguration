# Hyprland configuration

Files: `home-config/mathew/hyprland.nix` (loads the Lua files), `home-config/mathew/hyprland/*.lua`, `wallpaper/` and `palette/` (colours). Session start and the remote sessions: `docs/remote-access.md`. The bar: `docs/waybar.md`.

## Layout of the config

Home Manager writes `~/.config/hypr/hyprland.lua` with one `require("hyprland.<name>")` per entry of `extraLuaFiles`, in name order, and puts the files under `~/.config/hypr/hyprland/`.

| File | Holds |
|---|---|
| `session.lua` | the `hyprland.start` hook: when `HYPRLAND_START_LOCKED` is set (a remote start, not a login at SDDM) creates `HEADLESS-1`; the lock is `hyprlock-initial.service` (`hyprlock-initial.nix`) |
| `monitors.lua` | `DP-2` (2560x1440@180, 10 bit, VRR) and the virtual `HEADLESS-1` for Sunshine, to the right of `DP-2` so the two outputs do not overlap |
| `settings.lua` | gaps, rounding, blur, shadow, input, `misc` |
| `animations.lua` | curves and animations |
| `rules.lua` | window and layer rules |
| `binds.lua` | key and mouse binds |

A file is added in `hyprland.nix` and, if it is new, with `git add -N`.

## Login screen

SDDM runs its greeter under the same Hyprland (`sddm.nix`, `start-hyprland -- -c /etc/sddm/hyprland.lua`) with its own config `system-config/nixos/sddm-hyprland.lua`. Without a config the greeter's Hyprland drew its "config missing" banner and the default wallpaper, and showed them for about a second after the login. The monitor mode and the layouts are copied from `monitors.lua` and `layouts.nix` (another flake), so change them together. The theme is still catppuccin; the look of `style/` is not applied to it.

## Look

- Gaps 5/10, rounding 15 (the bar islands use 20), blur 4x3, inactive windows at 0.85 opacity. The window shadow is light and very soft, without offset: range 40, render power 2, black at alpha 0.2 when focused and 0.1 when not. It tells the window edge better than a border did, and an offset shadow drew a lobe under the window; the values are tuned by eye.
- Windows have no border: the active one is told by the inactive ones' opacity.
- **Style** (`style/default.nix`): the one place for the font, the two fill opacities (windows 0.8, floating panels 0.5, the same in both modes), the glass border (1 px, `outline_variant` at 0.28 opacity) and the blur behind, the matugen contrast of the palette (`paletteContrast`, 0), the corner radii (panel 20 px for bar islands, notifications, launcher panels, lock field and tooltip; inner 12 px for a workspace button and the selected launcher row; window 15 px), the gaps (10 px, inner 5 px). Its `tokens` are `@name@` placeholders (`@radius@`, `@gap@`, `@font_family@`, `@panel_alpha@`...) in the waybar CSS, the rofi theme, the Lua files and the matugen templates; `subst` fills them in at build time, and `mako.nix`, `hyprlock.nix` and `kitty.nix` read the same values as Nix attributes. A new look value is one attribute and one token. The blur is a layer rule per namespace in `rules.lua` (`glassLayers`). The rofi layer namespace is `rofi`.
- Animations: `speed` is in deciseconds. Windows use a critically damped spring (response 0.4 s, Apple's "smooth" idea: no overshoot), workspaces an ease-out curve with a sharp start and a long soft stop; closing windows, fades and layers are short ease-outs.

## Wallpaper palette

`wallpaper/palettes.nix` runs `matugen` over every image at the top level of `assets/wallpapers` (a subdirectory is ignored) at build time. Each wallpaper and mode is a separate derivation, so Nix schedules renders in parallel up to its build-job limit. A link farm assembles the rendered files under `wallpaper-palettes/<image>/<mode>/`. `theme-mode apply` (`wallpaper/theme-mode.sh`) copies the set of the current wallpaper and mode to `~/.local/state/wallpaper-palette/` (rename per file, so no consumer reads a half-written file), writes the mode into the file `mode` there, sets the GTK theme, the icon theme and the colour scheme in dconf and reloads the consumers; `set-random-wallpaper.sh` calls it. Which set is current, in order: the wallpaper name in `wallpaper`, the mode in `mode`.

| Template | Consumer | Reload |
|---|---|---|
| `waybar.css` | `waybar.css` imports it: `@define-color <matugen name>` for every colour | `systemctl --user try-reload-or-restart waybar` |
| `mako` | `include=` in the mako config | `makoctl reload` |
| `kitty.conf` | `include` in `kitty.conf` | `SIGUSR1` to every kitty |
| `rofi.rasi` | `@import` in `rofi-glass.rasi`: `<matugen name>` and `<name>-panel` for every colour, names with hyphens: rasi has no underscore in names | none: read at each start |
| `hyprlock.conf` | `source=` in `hyprlock.conf`: `$<matugen name>` for every colour and `$<name>_panel` with the panel alpha (hyprlang cannot change the alpha of a variable) | read at each lock |
| `gtk.css` | `@import` in `~/.config/gtk-3.0/gtk.css` and `gtk-4.0/gtk.css` (`gtk.nix`): the named colours of adw-gtk3 and libadwaita | none: a GTK window reads it when it opens |
| `kvantum-dark.sed`, `kvantum-light.sed` | not copied: `palettes.nix` applies the one of the mode with `sed` to Kvantum's KvFlat (dark) or KvFlatLight (light), which gives `KvMatugen.kvconfig` and `KvMatugen.svg`; `qt.nix` links the two into `~/.config/Kvantum/KvMatugen/`, so the theme name stays the same in both modes | none: a Qt window reads them when it opens |

`hyprpaper.service` turns active only once its IPC socket exists (`ExecStartPre` removes a stale socket, `ExecStartPost` waits for the new one, both in `hyprpaper.nix`; the name `.hyprpaper.sock` is hardcoded in hyprpaper, so the wait fails with a message after 10 s if an update renames it), and `random-wallpaper` runs before `waybar.service`, so the script's reload does not hit a waybar that is still starting (SIGUSR2 kills it); that reload is `--no-block`, because waiting for a unit that is ordered after the script itself deadlocks the start (and a `switch`). `~/.local/state/wallpaper-palette/wallpaper` names the current wallpaper, and `lock-background` in the same directory links to its image: hyprlock shows it as its blurred background, because a screenshot is empty when the lock starts before the first wallpaper (remote start). Every `switch` refreshes the directory from that wallpaper's palette (the first wallpaper by name before the script ever ran) with `theme-mode seed` before user units reload. After the unit transition, `theme-mode reload` restarts an active Waybar and tells Mako and Kitty to reread the palette. Both commands can find the user bus via `/run/user/<uid>/bus` when the launching shell has no session environment. With no user bus, they skip notifying the consumers; the consumers then read the palette when they next start. A build fails when matugen leaves a template file out for any wallpaper. The cache of clipboard thumbnails is separate (`clipboard-pick.sh`). A new colour role is one line in the template; a new consumer is one template, one entry in `templates` and a reload line.

## Terminal and shell colours

`palette/kitty.conf` also sets the 16 ANSI colours. Black stays dark and white light in both modes (the only mapping that depends on the mode, `ansi` in `style/`): in the dark mode black is `surface_container_highest`, white `on_surface_variant` and bright white `on_surface`; in the light mode black is `on_surface`, white `surface_container_highest` and bright white `surface_container_lowest`; bright black is `outline`, and blue/magenta/cyan are `primary`/`tertiary`/`secondary`. Red is the Material `error` colour; green and yellow are matugen custom colours (`[config.custom_colors]` in `wallpaper/palettes.nix`) with `blend = true`, harmonised to the wallpaper. The bright colours equal the normal ones. Everything that uses ANSI colours follows the wallpaper: `zsh-syntax-highlighting`, the autosuggestion (`fg=8`), `ls`, `git`, TUIs. Colours 16 and 17 (outside the 16 ANSI colours) are `on_secondary_container` and `secondary_container`, the text and the fill of the prompt pill below: dark with light text in the dark mode, light with dark text in the light mode, as the bar's active workspace and the GTK selection (`accent_bg_color`) are.

The prompt (`zsh-theme.nix`, starship, `mathew` only: `shared/zsh.nix` is also imported by hosts without a palette) is one pill (user name, host name in an ssh session only, directory, git, nix shell, command duration) split by a thin Powerline arrow followed by `❯` and the command on the same line. The configured local kitty uses colour 17 for the fill and 16 for the text (the accent container, above). Other terminals and SSH sessions use ANSI blue for the fill and ANSI black for the text. The caps are half-circle Powerline glyphs in the fill colour. The fill is opaque on purpose: kitty can make a cell background translucent (`transparent_background_colors`) but a glyph is always opaque, so a translucent pill shows a body of a different shade than its caps. The pills need a Nerd Font in the terminal, also on a client that connects over ssh, whose own ANSI palette colours them (the wallpaper palette exists only in kitty on this host). To render the prompt without the ssh host pill from a script run in an ssh session, unset the variables: `env -u SSH_CONNECTION -u SSH_CLIENT -u SSH_TTY starship prompt`.

## Binds

| Keys | Action |
|---|---|
| `SUPER+arrows` / `+CTRL` / `+ALT` | focus / resize by 40 px / swap |
| `SUPER+wheel` | next or previous workspace |
| `Print`, `SHIFT+Print`, `CTRL+Print` | `hyprshot` region, window, output (file in `~/Pictures/Screenshots` and clipboard) |
| `SUPER+SHIFT+C` | `hyprpicker -a` |
| `SUPER+V` | clipboard history (`clipboard-pick`): `cliphist` list in `rofi -dmenu`, the choice goes to the clipboard and is pasted with `wtype` (`CTRL+SHIFT+V` in a terminal, `CTRL+V` elsewhere; the terminal classes are listed in `clipboard-pick.sh`) |
| `SUPER+L` | `hyprlock` (not started again while one runs) |

rofi is the launcher (`SUPER+E`, drun mode, pressing it again closes it) and the clipboard picker (`SUPER+V`), both in `rofi.nix` with the theme `rofi-glass.rasi`: the input field and the list are two separate glass panels, which fuzzel (one surface) cannot draw. The picker lists an image as a thumbnail right of its text (the theme passed with `-theme-str` in `clipboard-pick.sh`, so text entries have no gap on the left; the launcher keeps icons on the left). A larger icon for the selected row does not work: rofi takes the icon size from the widget, not from the row state (`clipboard-pick.sh` renders each image entry once into `~/.cache/clipboard-pick`, deleted after 7 days). hyprlauncher was replaced: it has no border or panel settings and its `--dmenu` mode (0.1.7) reads a list but never prints the choice, so it cannot feed `cliphist decode`. `services.cliphist` stores text and images from `wl-paste`.

## Rules

- Blur for every glass layer (`waybar`, `notifications`, `rofi`); `ignore_alpha = 0.1` leaves fully transparent areas, such as the gaps between the bar islands, unblurred. `blur_popups = true` in the same rule blurs the popups of the layer (the Waybar menus and tooltips).
- `suppress_event = "maximize"` for every window: kitty and other apps request to start maximized, and a maximized window fills the work area over the others instead of joining the layout (`hyprctl clients` shows `fullscreen: 1`).
- `immediate = true` for `steam_app_.*`: tearing, which lowers latency, applies only to a fullscreen window and needs `allow_tearing` in `settings.lua`.
- The bar layer rule (blur): `docs/waybar.md`.

## Troubleshooting

- Notifications or `kitty` have the default colours: the file in the same directory is missing; run `~/.local/bin/set-random-wallpaper.sh`.
- `SUPER+V` shows nothing: `systemctl --user status cliphist`. The entry is copied but not pasted: the focused window's class is not in the terminal list of `clipboard-pick.sh` (`hyprctl activewindow -j`), or the app ignores virtual-keyboard input.

## File managers

`Super+R` opens Yazi in a kitty window of the class `yazi`, `Super+Shift+R` opens Nemo. Nemo is the default for folders (`inode/directory` in `xdg.nix`), so "show in folder" from a browser or a messenger opens it; it is also the one that takes drag and drop.

- **Yazi** (`yazi.nix`) uses the wallpaper palette for the current row and active tab (`secondary_container` with `on_secondary_container`) and for the parent row (`surface_container_highest` with `on_surface`). Reopen Yazi after a palette change to refresh its row and tab colours. The status bar uses explicit palette pairs for the mode, size and position. Its other terminal colours come from kitty. The previews need `ffmpegthumbnailer`, `poppler-utils`, `imagemagick`, `p7zip`, `fd`, `fzf`, `zoxide`, `ripgrep`, `jq`, which `programs.yazi.extraPackages` puts on Yazi's own `PATH` only. The shell function `y` changes the shell directory to where Yazi was left. Markdown is rendered in the preview by `glow` through the `piper` plugin (`prepend_previewers` in `yazi.nix`) with a wallpaper palette style. Inline code uses `on_surface` on `surface_container_highest` for readability in both modes.
- **GTK** (`gtk.nix`): the theme `matugen-glass` is a thin theme of two files that `@import` `adw-gtk3-dark` and add `gtk/theme.css`: the corner radius of `style/` and, for Nemo only, the translucent window (every layer, window, sidebar, toolbar, status bar and file list, at `windowAlpha` 0.8) and larger rows and buttons, in the desktop font at 13 pt (the GTK font of every other application stays `Sans` 11: Chrome in its "GTK" appearance takes the GTK font and the named colours for its own interface, and a monospace font made it look wrong). The window blur is the global `decoration.blur` of Hyprland, which blurs any translucent window, so Nemo needs no window rule. The colours are not in the theme: they come from `palette/gtk.css` through the user `gtk.css`, which libadwaita reads too (it ignores the theme name). `palette/gtk.css` defines every matugen colour under its own name and then the adw-gtk3 and libadwaita named colours as a table of those names: `accent_color` is `primary`; the active fill (`accent_bg_color`, the header bar, the selected row) is `secondary_container` with `on_secondary_container`; the window and the lists are `surface`, the cards `surface_container`, the sidebar, popovers and dialogs `surface_container_high`; the text is `on_surface`; the borders are `outline_variant`; destructive and error are `error`, success and warning the custom `green` and `yellow`.
- **Qt** (`qt.nix`): `qtct` as the platform theme and Kvantum as the style with the theme `KvMatugen`: KvFlat recoloured by `palette/kvantum-dark.sed` and `kvantum-light.sed`. The sed script maps the grey steps of the SVG to the `surface_container*` roles, the light greys to `outline` and `on_surface`, and the blues to `primary` (the accent) and `secondary_container` (the selection). A Qt window is solid, without the glass. Qt applications of this host: Telegram, OBS, qBittorrent, Mumble, Polychromatic, Audacious, hyprpwcenter, Gwenview; LibreOffice draws with its own toolkit.
- The palette of a window is fixed when it opens: after a wallpaper change an open Nemo or Qt window keeps the old colours until it is reopened.
- A button, a popup or a Nemo area looks wrong (a colour of KvFlat that the sed script does not map, a Nemo node that `gtk/theme.css` does not select): look at the node with `GTK_DEBUG=interactive nemo` and add the selector, or run the SVG colours of the base theme through `grep -oiE '#[0-9a-f]{6}'` and add the missing one to `palette/kvantum.sed`.

## Light and dark mode

The desktop has a dark and a light palette of the same wallpaper (`Wallpaper palette`). `theme-mode` (`wallpaper/theme-mode.sh`, built in `wallpaper/default.nix`; commands `apply [light|dark]`, `toggle`, `auto`, `status`, `daemon`) switches them. The user service `theme-mode.service` starts after the graphical session and wallpaper, runs `theme-mode auto` before the bar starts and then `theme-mode daemon`: a loop of `sunwait wait` (sleeps until the next sunrise or sunset; the coordinates are `location.nix`, the same as the night colour of `wlsunset.nix`) and `theme-mode auto`, which takes the mode of `sunwait poll` (day, twilight included, is light). The sun, not the wallpaper, decides; there is no day and night wallpaper. `sunwait` has no module in NixOS or Home Manager, only the package. It sleeps with `sleep()`, which does not count a suspend, so a suspend delays the change by its length; nothing here suspends on its own.

- **The button** (`custom/theme` in the right island of the bar, between the microphone and the failed-unit dot): the glyph is the current mode (sun, moon). A left click runs `theme-mode toggle`: the other mode, marked `manual` (file `manual` in the palette directory, the glyph turns the accent colour), until the next sunrise or sunset, when the daemon's `auto` ends it. A right click runs `theme-mode auto` at once.
- **What changes**: the palette files (waybar and kitty reload at once, mako too; rofi and hyprlock read theirs when they start), the dconf keys `color-scheme` (`prefer-dark` or `prefer-light`, which a site reads as `prefers-color-scheme`), `gtk-theme` (`matugen-glass-dark` or `-light`) and `icon-theme` (`Paper-Mono-Dark` is made for a dark background, so the light mode uses `Paper`). Open GTK windows (Nemo, Chrome in the GTK appearance) re-theme at once; a Qt window takes the mode when it opens.
- **Opacity**: two values in `style/default.nix`, the same in both modes: windows 0.8 (the terminal background and every layer of Nemo) and floating panels 0.5 (bar islands, rofi, mako, the lock field); the glass border has the panel opacity too. At 0.3 and 0.65 the text lost its contrast when the wallpaper brightness was opposite to the mode. A light panel is mostly the wallpaper, so dark text over a dark photograph can get hard to read; if it does, a per-mode value would have to come back.
- **Colours and contrast**: no colour is adjusted by hand. Matugen uses its default contrast, `--contrast=0` (`paletteContrast` in `style/default.nix`), in both modes. Waybar and Rofi expose the matugen colours as named roles. Each component maps those roles to its own elements: primary text and icons `on_surface`, secondary text `on_surface_variant`, accent `primary` with `on_primary` on it (cursor, links, terminal text selection, the manual theme icon), the active fill `secondary_container` with `on_secondary_container` (active workspace, the current Rofi row, the current Yazi row and active tab, the prompt pill, the Nemo header bar, `accent_bg_color`), window panels `surface_container_high`, backgrounds `surface`, the glass fill `surface_container_high` with its border `outline_variant` (fill at 0.5 opacity and border at 0.28), errors `error`. `wallpaper/contrast.py` fails the build when a pair falls below its floor, for every wallpaper and mode: `on_surface` on `surface` 7:1, `on_surface` on `surface_container_highest` 4.5:1 for inline code and the Yazi parent row, `on_surface_variant`, `primary`, `error`, `green` and `yellow` on `surface` and `on_secondary_container` on `secondary_container` 4.5:1, `outline` on `surface` 3:1. There are no ceilings.
- **Troubleshooting**: `theme-mode status` shows the mode and whether it is manual; the daemon logs with `journalctl --user -u theme-mode`; after a `switch` the mode of the sun is applied again at the next sunrise or sunset or by a right click on the button. Without a session bus (a plain tty) `theme-mode apply` copies the palette and skips dconf and the reload.
