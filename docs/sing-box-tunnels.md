# sing-box tunnels and the Tailscale exit node

How the tunnels and the exit node work and why. The units and rules are in `system-config/nixos/sing-box.nix`, `awg-exit-node.nix` and, for the Tailscale service and the `--advertise-exit-node` flag, `tailscale.nix`; this file holds what the code does not show.

## Why AmneziaWG sits under sing-box

- The `main` instance reaches the internet through a server-issued AmneziaWG `.conf` (agenix: `secrets/awg-main.age`, delivered to `/etc/sing-box/main-awg.conf`). It listens on port 2080, which `HTTP(S)_PROXY` and the Nix daemon use.
- sing-box has no AmneziaWG outbound (upstream closed the request as not planned, and the nixpkgs build has no `with_awg`), so the kernel module (`wg-quick` with `type = "amneziawg"`) holds the tunnel and sing-box only binds its `proxy` outbound to `awg0`. What sing-box still gives: domain-based routing for `HTTP_PROXY` clients, DNS for proxied domains through the tunnel, and the same instance interface as the vless one (`credits`).
- Fail closed: `bind_interface` makes a matched domain fail when the tunnel is down instead of leaving through `eno1`.
- The server `.conf` is stored verbatim; `awg-prepare.sh` derives the runtime config: it drops `DNS` (would replace the system resolver) and hooks (a third-party file must not run commands as root), puts the routes into table 51820 so `main` stays untouched, and keeps IPv4 only.
- Source-address policy rule `from <tunnel address> lookup 51820` (priority 5000) is what sends sing-box's bound sockets into the tunnel.
- For matched destinations, the `proxy` outbound resolves IPv4 addresses via Cloudflare DoH at `1.1.1.1` through that same outbound. The literal IP avoids a bootstrap lookup and TLS verifies `cloudflare-dns.com`.

## Kinds: one definition per tunnel kind

`sing-box.nix` holds `instances` (the one attrset to edit; its fields are typed, so a wrong port, `kind` or path fails with the option name, and the settings of one kind sit in a sub-attrset of the same name: `awg = { interface; table; }`, `vless = { runtimeKey; fetchIntervalSec; onBootSec; }`, required only for instances of that kind), the checks common to all kinds, the main unit `sing-box-<name>`, the user and the merge. Everything that differs per kind is in `sing-box/kinds/<kind>.nix` (a plain function, not a module) and `sing-box/kinds/<kind>.py`; `generate-config.py` keeps the shared part of `config.json` and the `KINDS` registry. The generator is copied (`install -D`) into one store directory, because Python imports `kinds` from the real directory of the script.

A kind file takes `{ pkgs, lib, name, inst, secretFile, shared, ... }` (`secretFile` is the agenix file, `shared` the common helpers) and returns any of these; the dispatcher fills the rest with defaults:

| Field | Meaning |
|---|---|
| `services`, `timers` | units the kind owns, keyed by unit name; may extend a generated one (`wg-quick-<iface>`) |
| `extraConfig` | other NixOS config of the kind, merged with `lib.mkMerge` |
| `deps`, `restartTriggers` | added to `wants`/`after` and `restartTriggers` of `sing-box-<name>` |
| `environment`, `serviceConfig` | additions to the main unit (`SING_BOX_<KIND>_*`, `LoadCredential`) |
| `failureUnits` | names for `services.failure-notify.units` |
| `exitTunnel` | `null`, or `{ interface, table }` when the kind owns a kernel interface and a table |
| `claims` | values that must differ between instances (`interface`, `table`) |
| `assertions` | kind-specific checks with messages |

The Python side exposes `build(env)` returning `{ outbound, dns, default_domain_resolver }` (`None` where the kind adds nothing).

Adding a kind: a line in `kindFiles` of `sing-box.nix`, `kinds/<kind>.nix`, `kinds/<kind>.py` with an entry in `KINDS`, and `kinds/test_<kind>.py`. A test fails when `kindFiles`, `kinds/*.nix`, `kinds/*.py` and `KINDS` disagree; a kind that returns a field not in the table is an evaluation error. Unit names are fixed in the kind file once; `deps` and `failureUnits` use the same names, and the box module disables some of them by name.

## Accepted secret formats

- `awg-<name>.age` holds either the server `.conf` or an Amnezia `vpn://` string (the share string of the Amnezia app). `awg-prepare.sh` and `vless-fetch.sh` both run `sing-box/decode-vpn.py <mode> --passthrough` (stdin only): input that starts with `vpn://` is decoded, anything else is copied unchanged (a `.conf` here, a link or URL for `vless-fetch.sh`). From there on both take the same path, so the same tunnel gives the same runtime config either way.
- A `vpn://` string is base64url of a Qt `qCompress` blob (4-byte big-endian length, then zlib) holding JSON. `containers[]` lists the containers; the container of `amnezia-awg` and `amnezia-awg2` keeps the `.conf` text in `awg.last_config`, which is itself a JSON string with the text in its `config` field. The decoder uses that text only and fails when it is missing: it does not rebuild a config from the other fields of the JSON, since nothing could check such a config.
- Container selection: `default_container` when it is an AmneziaWG container; otherwise the only AmneziaWG container; otherwise an error (none, or several without a default among them). A string whose default is another protocol still feeds an `awg` instance if it carries exactly one AmneziaWG container.
- The decoder rejects a `PrivateKey` that is an unreplaced template placeholder, a payload over 1 MiB after decompression, and a length header that does not match. It never prints values from the string; to see which keys a string carries (for example the AWG 2.0 `S3`, `S4`, `I1`-`I5`) run `decode-vpn.py inspect < string`: it prints key paths and types, never values.
- Whether the pinned kernel module and `amneziawg-tools` accept every AWG 2.0 key was checked only against the upstream master sources, not against the tags in nixpkgs; a rejected key shows as a failed `wg-quick-awg0`.
- `vless-<name>.age` may hold the `vpn://` string of an `amnezia-xray` container: `vless-fetch.sh` runs `decode-vpn.py xray`, which prints one `vless://` link for `generate-config.py` (its layout, with `last_config` as an object and the default container named `defaultContainer`, was read off a real string with `inspect`). Only `tcp` (`raw` in the Amnezia app) with `reality` is accepted, with or without `xtls-rprx-vision`, because that is what `generate-config.py` turns into an outbound correctly. `xhttp`, mKCP, grpc, ws, plain tls, vless encryption, header obfuscation and a missing public key are refused with a message, since `generate-config.py` would build a wrong outbound for them without an error. `spiderX` is dropped with a warning. An upstream sing-box build has no XHTTP or mKCP transport; they would need a separate `xray` process.
- A direct `vless://` link or a subscription response supports TCP (`tcp` or `raw`) and WebSocket (`ws`); other transports are rejected. Subscription responses may be plain text or base64. The fetch timer runs the oneshot repeatedly; a changed key restarts an already running sing-box instance asynchronously, while an unchanged key leaves it running.
- OpenVPN, Cloak and Shadowsocks containers of a `vpn://` string are not read yet: there was no real string to check their layout against. sing-box 1.14 has a native `openvpn-client` endpoint, which would make a system OpenVPN client unnecessary.
- `-awg-prepare` runs as root on a string that comes from outside, so its unit is sandboxed (no network, read-only system, private `/tmp`; the runtime directory stays writable) and its failure is reported through `failure-notify`.

## Data path

- A client that honours `HTTP(S)_PROXY` connects to `main` on 127.0.0.1. sing-box matches the name from the proxy request and opens a new socket: bound to `awg0` for a matched domain, or through `eno1` for the rest. `NO_PROXY` and `no_proxy` include the domains of other instances with a TUN so clients that honour these variables reach the corresponding TUN through the system resolver. An explicit proxy for `credits` is available on port 2081.
- Traffic that does not use the proxy and does not resolve a `proxyDomains` name leaves through `eno1` unchanged and never reaches sing-box. A name in `proxyDomains` reaches it through the TUN (next section), with or without `HTTP(S)_PROXY`.
- The exit-node path (below) is plain kernel forwarding from `tailscale0` into the tunnel; sing-box is not on it.

## Fake-IP TUN: programs that ignore the proxy variables

An instance with `tun` set (both do) gets a second inbound next to the proxy port, so Steam, Electron apps, `go` and `dotnet` tools reach its `proxyDomains` without per-program settings. The proxy port and `HTTP(S)_PROXY` stay as they were.

- **Link.** `systemd-networkd` creates a persistent `tun` link per instance (`sbtun-<instance name>`, at most 15 characters, owned by the `sing-box` user) and configures it: the address, a route of the fake range into it, and resolved's `DNS=` (the other host of the link's /30) with routing domains `~<proxyDomain>`. sing-box only attaches to the link (`CAP_NET_ADMIN` in the unit). It sets `auto_route = false`, so it installs no default route and nothing outside the fake range can enter it.
- **Names.** resolved sends only the `proxyDomains` (and their subdomains) to the DNS address of the link (the other host of the /30 of `address`); sing-box hijacks that DNS and the `fakeip` server answers A and AAAA with an address from `fakeRange`; any other query type (HTTPS, SVCB, TXT) gets an empty NOERROR from a second rule, because the `fakeip` server fails on it and the client would wait for a timeout. Both rules sit before the rules of the kind. Every other name uses the link DNS of the uplink and never touches sing-box. The DNS rule matches only the `tun-in` inbound, so the resolvers a kind uses for its own outbound stay as they are. The rule is a suffix match and sits first, before any rule of the kind. With a `tun` the route rule matches by suffix too, whatever `routeMatch` says: resolved sends every subdomain of a routing domain to sing-box, and a subdomain that stayed direct would be dialled through the system resolver, which answers with a fake address again. The proxy port matches the same way then. `store_fakeip` keeps the fake addresses over a restart.
- **Traffic.** A connection to a fake address enters the TUN; sing-box maps it back to the name and routes it to the `proxy` outbound. AWG uses its tunnel-bound DNS resolver. VLESS sends the destination name to the remote server, which resolves it using its own DNS configuration.
- **Fail closed.** The link outlives sing-box, so with sing-box stopped the names do not resolve at all (resolved times out, about 5 s per query) instead of resolving to the real address and leaving past the tunnel. This holds for every program and user, and the `proxyDomains` of `main` include broad suffixes (`microsoft.com`, `googleapis.com`): a crash loop of `sing-box-main` (a missing credential, a down `awg0`) takes those names out system-wide until the unit recovers. To get them back at once, stop the unit and drop the link's resolved settings: `resolvectl revert sbtun-<name>` (networkd restores them on its next reconfigure). Do not replace the persistent link with one that sing-box creates itself: then the routing domains vanish with it.
- **Stack.** The default stack (`mixed`) redirects each TCP connection to a listener of sing-box on the TUN address, so the kernel must accept that packet as input on the link. The NixOS firewall drops it unless the link is trusted; `sing-box.nix` sets `networking.firewall.trustedInterfaces` to the `sbtun-*` links. Only sing-box writes input packets into them. Without it the SYN reaches the link, no SYN-ACK follows and every connection times out. Measured against `gvisor` (which never hands a packet to the kernel's TCP): about half the CPU, no difference in memory (about 16 MB peak) or in the time of small requests.
- **Ranges.** Per instance `address` (host .1 or .2 of a /30 block) and `fakeRange` (a part of 198.18.0.0/15); the other host of the block is the DNS address. The blocks and the fake ranges must differ between instances; assertions enforce it, and that `routeMatch` is `domain_suffix` (see Names). Keep them away from Tailscale (100.64.0.0/10), the AWG address and the LAN.
- **Browsers.** Firefox and Chrome with DoH resolve names themselves and never see fake addresses; with any `tun` set, `sing-box.nix` switches DoH off by policy (`/etc/firefox/policies/policies.json`, `/etc/opt/chrome/policies/managed/dns.json`). Chromium and other browsers are not covered.
- **Check.** `resolvectl query <proxy domain>` answers with an address of the fake range and `link: sbtun-<name>`; `resolvectl query <other name>` has no `sbtun` link; `ip route get <fake address>` shows the TUN; `curl --noproxy '*'` to a proxy domain reaches the site. The sing-box unit is ordered after `systemd-networkd.service`: if it started first it would create a link of its own without the routing domains. The VM backend of the box applies the links and the resolved routing domains from this configuration, but sing-box needs the agenix credentials there, so it is started by hand under the `sing-box` user with `AmbientCapabilities=CAP_NET_ADMIN` and a config from `generate-config.py`.

## Exit node for the phone

- One AmneziaWG key allows one connection, and both the host and the phone need it. The phone selects this host as a Tailscale exit node and the host forwards that traffic into the same `awg0`: one WireGuard peer, no second key. With a second key, add a second interface and table instead.
- The instance that carries the exit node sets `exitNode = true` in `instances` (only a kind that returns `exitTunnel`, today `awg`; at most one: a failed assertion names the offenders). `sing-box.nix` derives the interface and table into `services.sing-box-tunnels.exitTunnel`, and `awg-exit-node.nix` and `tailscale.nix` read only that option. A kind that owns a kernel interface and a table returns `exitTunnel` from its definition (see below); any other kind refuses `exitNode` through an assertion.
- The exit node answers the phone's DNS through this host's resolved (tailscaled forwards to `127.0.0.53`), so a name in `proxyDomains` comes back as a fake address of a `tun`. `awg-exit-node.service` therefore adds `iif tailscale0 to <fakeRange> lookup main priority 5275` per fake range (before the exit rule at 5280): that traffic enters the TUN and sing-box sends it through the tunnel by name. Without the rule it falls into the exit table and the phone loads forever.
- Without such an instance the module adds no rule, blackhole or nft table, and `tailscale.nix` sets `--advertise-exit-node=false`: the flags of `tailscale set` are sticky, so only the explicit false form withdraws an earlier advertisement.
- `iif tailscale0 lookup <table>` has priority 5280, after Tailscale's `5270 lookup 52`: tailnet-to-tailnet traffic stays in the tailnet. Packets for the host itself (its tailnet and LAN addresses) hit the `local` table first, so murmur, Sunshine and the headless session work while the exit node is on. Other LAN devices are not reachable through it; add a `192.168.0.0/16` rule before 5280 if that is ever needed. Community reports say the order of Tailscale's own rules (5210-5270) can change between boots with the start order of services; check `ip rule` after a reboot.
- A `blackhole default` in the table keeps the phone's traffic from falling through to `main` (the real uplink and address) while the tunnel is down. `awg-exit-node.service` therefore does not depend on `wg-quick-<interface>`: the rule and the blackhole stay when the tunnel stops or fails, and only a stop of `awg-exit-node` itself removes them (`wg-quick` deletes only the routes of the interface).
- The tunnel is IPv4-only, so forwarded IPv6 from `tailscale0` is rejected (not dropped: a drop makes dual-stack clients wait for a timeout before using IPv4). `awg0` has MTU 1280, so TCP SYN and SYN-ACK are clamped to the route MTU in both directions; masquerade is set on the tunnel interface explicitly.
- Who may use the exit node is Tailscale policy (admin console, ACL), not repository state. After the first `switch` the exit node has to be approved there once.

## Things to know

- `systemd.network.wait-online` is disabled, so `network-online.target` does not wait for a default route; sing-box logs `missing default interface` at boot and works afterwards. This is cosmetic.
- `awg-exit-node.service` starts before `systemd-networkd` at boot, and networkd removes routes it did not configure at its start: with the default `ManageForeignRoutes` the blackhole was missing after a reboot (a manual restart of the unit brought it back). The unit is therefore ordered after `systemd-networkd.service`; `ip -4 route show table <table>` must list the blackhole after a reboot, and if it does not, `ManageForeignRoutes=false` in `network.nix` is the broader fix that was verified.
- Renaming an instance renames its `-awg-prepare` unit, so `wg-quick-awg0` restarts on `switch`: the tunnel and the phone's exit node drop for a second. Changing the decoder or `awg-prepare.sh` restarts them the same way.
- Leftovers of a removed instance are not cleaned by `switch` (`/var/lib/sing-box/<name>`, old runtime files in `/etc/sing-box`); only the owner removes them.
- A tunnel address change on the server side needs a restart of `sing-box-main`: the generator bakes the address into `config.json` (`restartTriggers` on the secret does this on `switch`).
- Tests of the decoder and of `awg-prepare.sh` on synthetic strings: `python3 -B -m unittest discover -s system-config/nixos/sing-box -p 'test_*.py'`. The box disables these units, so the sandbox of `-awg-prepare` and the exit-node unit are exercised only by the owner's `switch`.
